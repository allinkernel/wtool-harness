# 05 写一个新项目

## 先选形态

| 我要做的事 | 形态 | 需要的文件 |
|---|---|---|
| 提供别名/函数/环境变量 | **env 型** | `wtool.xml` + `env.zsh`（和/或 `env.bash`） |
| 让应用去某个位置读配置 | **link 型** | `wtool.xml` + 被链接的文件 |
| 改系统配置文件（换源等） | **system-file 型** | `wtool.xml` + 内容文件（或用 `kind` 让引擎生成） |
| 拉上游源码 + 编译安装 | **source 型** | `wtool.xml` + `overlay/wsw.sh` |

一个项目可以同时是多种（比如 tmux 既是 env 又有 link，os/ubuntu 既有 system-file 又有 provision）。

---

## 起手式：用脚手架

```sh
cd ~/self/wtool
./bootstrap/wtool.sh scaffold tools/mytool --id tools/mytool
```

会生成：

```
tools/mytool/
├── wtool.xml       声明文件（带注释的模板）
├── env.zsh         被注入的部分
├── install.sh      ← 存根，勿手改
└── uninstall.sh    ← 存根，勿手改
```

然后编辑 `wtool.xml` 和 `env.zsh`，最后：

```sh
./bootstrap/wtool.sh validate tools/mytool          # 只校验
./bootstrap/wtool.sh install tools/mytool --dry-run # 看计划
./bootstrap/wtool.sh install tools/mytool
```

## `wtool.xml` 人话版

```xml
<?xml version="1.0" encoding="UTF-8"?>
<wtool schema="1" id="tools/mytool" priority="40">

  <!-- 要被 source 的部分。shells 省略时按扩展名推断 -->
  <env src="env.zsh" shells="zsh" priority="40"/>

  <!-- 要被软链的部分。src 相对本目录，dest 相对 $HOME -->
  <link src="mytool.conf" dest=".config/mytool/mytool.conf"/>

</wtool>
```

### 根元素 `<wtool>`

| 属性 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `schema` | ✅ | — | 格式版本，当前只支持 `1` |
| `id` | 否 | 目录名 | **对外契约**：出现在 `~/.wtool/links/<id>` 和 rc 块标记里。改了必须重装 |
| `priority` | 否 | 100 | 决定 rc 块的先后，数值小的先加载 |

### `<env>` —— 要被 source 的部分

| 属性 | 说明 |
|---|---|
| `src` | 相对本目录的文件 |
| `shells` | `zsh` / `bash` / `sh`，逗号分隔；省略时按扩展名推断 |
| `priority` | 覆盖根元素的优先级 |

扩展名推断：`env.zsh` → 只注入 `~/.zshrc`；`env.bash` → 只注入 `~/.bashrc`；
`env.sh` → 两个都注入。

**写 `env` 文件的规矩**：

```zsh
# ✓ 只导出、只定义，没有副作用
export MYTOOL_DIR="$WTOOL_PROJECT_DIR"     # 立刻把稳定地址拷进自己的变量
alias mt='mytool --fast'
mytool_helper() { ... }

# ✗ 不要这样
echo "loaded!"                              # 每次开 shell 都刷屏
export PATH="$(cd "$(dirname "$0")" && pwd)/bin:$PATH"   # 别自己算路径
some_command_that_writes_files              # 不要在 source 时干活
```

> **为什么**：`env` 文件可能被 source 多次（重开 shell、`source ~/.zshrc`），
> 而且多个项目的块会依次覆盖 `WTOOL_PROJECT_*` 这三个变量。

### `<link>` —— 要被软链的部分

| 属性 | 说明 |
|---|---|
| `src` | 相对本目录；必须存在、必须在本项目内 |
| `dest` | **相对 `$HOME`**；不允许绝对路径、不允许 `..` |
| `force` | 该条允许覆盖已存在的非软链（会先备份） |
| `optional` | `src` 不存在时跳过（不报错） |

### `<system-file>` —— 改系统配置文件

| 属性 | 说明 |
|---|---|
| `dest` | 绝对路径；配 `kind` 时可写 `auto` 让引擎决定 |
| `src` | 自己写的内容文件（相对本目录） |
| `kind` | `apt-mirror` / `yum-mirror` / `distro-mirror`：引擎按发行版自动生成 |
| `mirror` | `ustc` / `tuna` / `aliyun` |
| `mode` | `replace`（备份后覆盖）/ `add`（不存在才建）/ `disable`（原文件改名禁用） |
| `backup` | 默认 `replace` 时为 `true` |
| `when` | 条件，如 `os:ubuntu` |

```xml
<!-- 换源：引擎自动识别 ubuntu + noble，生成 deb822，写前备份，卸载自动还原 -->
<system-file kind="apt-mirror" mirror="ustc" dest="auto"
             mode="replace" backup="true" when="os:ubuntu"
             desc="apt 源换成 USTC"/>
```

**它是可逆的**（备份 + journal），但需要 root，所以只在 `--with-system` 时执行。

### `<source>` + `<provision>` —— 源码编译型项目

```xml
<source url="https://github.com/neovim/neovim.git"
        ref="v0.10.4"                 <!-- 必填：固定到 tag/commit -->
        dir="$WTOOL_SRC/nvim"         <!-- 默认 ~/.wtool/src/<id末段> -->
        branch="wsw"                  <!-- 本地分支名 -->
        overlay="overlay"/>           <!-- 要铺进源码树的目录 -->

<provision src="wsw.sh"               <!-- 先找源码树，再找项目根 -->
           marker="nvim-{ref}"        <!-- 幂等标记 -->
           when="os:ubuntu"
           desc="编译安装 neovim"/>
```

引擎会：
```
clone/fetch  →  checkout --detach <ref>  →  checkout -B wsw
             →  把 overlay/* 铺进源码树  →  提交到 wsw 分支
             →  在源码树里执行 wsw.sh
```

**`wsw.sh` 的约定**（你的习惯，正式固定下来）：

```sh
#!/bin/sh
set -eu
# 引擎已注入这些变量：
#   WTOOL_PREFIX       编译安装前缀（= ~/.wtool/usr）—— 只准往这里装
#   WTOOL_SOURCE_DIR   源码树路径
#   WTOOL_SOURCE_REF   固定的 ref
#   WTOOL_JOBS         nproc
#   WTOOL_OS_ID / WTOOL_ARCH …

mkdir -p "$WTOOL_PREFIX"
make CMAKE_BUILD_TYPE=Release \
     CMAKE_INSTALL_PREFIX="$WTOOL_PREFIX" \
     -j"$WTOOL_JOBS"
make install -j"$WTOOL_JOBS"
```

要求：**幂等**（重复执行安全）、**只写 `$WTOOL_PREFIX`**、不碰系统目录。
装完 `$WTOOL_PREFIX/bin` 已经在 PATH 上（bootstrap 项目的 env 负责）。

### `<include>` —— 机器本地覆盖

```xml
<include src="wtool.local.xml" optional="true"/>
```

把不想入库的差异放在 `wtool.local.xml` 里，用 `.gitignore` 忽略它。

## 命名与优先级约定

| 路径前缀 | 放什么 | 建议 priority |
|---|---|---|
| `bootstrap/` | 引擎自己 | 5 |
| `os/` | 系统层（换源、基础包） | 5 |
| `shell/` | shell 相关（oh-my-zsh、zsh 配置） | 10 ~ 20 |
| `tools/` | 命令行工具（repo 辅助、脚本） | 30 ~ 45 |
| `terminal/` | 终端相关（tmux、fzf） | 50 ~ 60 |
| `editor/` | 编辑器 | 70 |
| `build/` | 源码编译型 | 80 |
| `themes/` | 主题（无 rc 注入） | — |

**priority 之间的空隙**是留给你插队的。

## 校验清单（`wtool validate` 会检查）

- XML 能解析、根元素是 `<wtool>`、`schema` 已知
- `<env>` 的 `src` 存在、shell 名已知
- `<link>` 的 `src` 存在且在本项目内、`dest` 不逃出 `$HOME`
- 同一清单内 `dest` 不重复
- `dest` 没被**其它项目**在 registry 里登记（跨项目冲突）
- `dest` 在磁盘上不存在，或已经是正确的软链

自定义元素请用 `x-` 前缀；未知元素一律报错（避免拼写错误悄悄失效）。
