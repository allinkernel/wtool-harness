# 03 命令速查

引擎入口是 `bootstrap/wtool.sh`。
装完 `bootstrap` 项目后，`wtool` 命令会在 PATH 上（等价于 `wtool.sh`）。

## 全部命令

| 命令 | 作用 | 典型用法 |
|---|---|---|
| `install` | 建软链 + 写 rc 块（**可逆**） | `wtool install terminal/tmux` |
| `uninstall` | 精确撤销某项目做过的事 | `wtool uninstall terminal/tmux`<br>`wtool uninstall --id terminal/tmux` |
| `provision` | 换源 / 装包 / 编译（**不可逆**） | `wtool provision os/ubuntu --with-system` |
| `bootstrap` | 全工作区按优先级依次 provision + install | `wtool bootstrap --with-system` |
| `list` | 列出所有登记的路径 → 项目 | `wtool list` |
| `status` | 检查登记的软链是否还在 | `wtool status` |
| `doctor` | 引擎版本、路径、系统信息 | `wtool doctor` |
| `env` | 输出可用环境变量（带中文说明） | `eval "$(wtool env)"` |
| `scaffold` | 生成新项目的骨架 | `wtool scaffold tools/new --id tools/new` |
| `validate` | 只校验清单，不做事 | `wtool validate terminal/tmux` |
| `version` | 引擎版本 | `wtool version` |

## 通用参数

| 参数 | 作用 | 说明 |
|---|---|---|
| `--dry-run` | 只打印计划，零副作用 | 任何破坏性操作前先跑这个 |
| `--force` | 绕过检查 | 工作区脏 / 覆盖已存在的软链 / 目标非 git 仓 |
| `--with-system` | 允许改 `$HOME` 之外的文件 | 只对 `provision` / `bootstrap` 有意义；默认不动系统 |

## 环境变量

### 长期存在（装完 `bootstrap` 项目后，每次开 shell 都有）

| 变量 | 值 |
|---|---|
| `WTOOL_PREFIX` | `~/.wtool/usr` —— **编译安装只准往这里装**，删掉即卸载 |
| `WTOOL_OS_ID` / `WTOOL_OS_VERSION` / `WTOOL_OS_CODENAME` / `WTOOL_OS_LIKE` | 探测自 `/etc/os-release`（如 `ubuntu` / `24.04` / `noble` / `debian`） |
| `WTOOL_ARCH` / `WTOOL_JOBS` | `uname -m` / `nproc` |
| `PATH` | 追加 `$WTOOL_PREFIX/bin` 和 bootstrap 的 `bin/`（`wtool` 命令） |

### 只在 source 期间有效（rc 块导出，会被后加载的块覆盖）

| 变量 | 值 |
|---|---|
| `WTOOL_PROJECT_ID` | 如 `terminal/tmux` |
| `WTOOL_PROJECT_DIR` | `~/.wtool/links/<id>` —— 稳定地址 |
| `WTOOL_PROJECT_ROOT` | 项目真实路径 |

用法：在 `env.zsh` 里**立刻拷进自己的变量**，例如
`export WTOOL_TMUX_DIR="$WTOOL_PROJECT_DIR"`。

### 只在 provision 任务执行期间有效（引擎临时注入）

| 变量 | 值 |
|---|---|
| `WTOOL_SOURCE_DIR` | `<source>` 拉下来的源码树路径 |
| `WTOOL_SOURCE_REF` | 固定的那个 ref |

### 引擎自己的开关（可用环境变量覆盖，一般用命令行参数即可）

| 变量 | 默认 | 作用 |
|---|---|---|
| `WTOOL_HOME` | `$HOME` | 被管理的家目录（测试用） |
| `WTOOL_STATE` | `~/.local/state/wtool` | 状态目录 |
| `WTOOL_PREFIX` | `~/.wtool/usr` | 编译安装前缀 |
| `WTOOL_SRC` | `~/.wtool/src` | 源码树根目录 |
| `WTOOL_ROOT` | bootstrap 的上级目录 | 工作区根（`bootstrap` 扫描用） |
| `WTOOL_BOOTSTRAP` | 存根自动查找 | 显式指定引擎位置 |

## 常用组合

```sh
# 先看一遍全工作区会做什么（最安全的第一步）
wtool bootstrap --with-system --dry-run --force

# 装完引擎后立刻看环境变量对不对
eval "$(wtool env)"; echo "$WTOOL_PREFIX $WTOOL_OS_ID $WTOOL_OS_VERSION"

# 检查有没有人把软链删了
wtool status

# 卸掉一个项目（连带它写的 rc 块和系统文件备份还原）
wtool uninstall shell/zsh

# 编译型项目：先看计划，再执行
wtool provision build/nvim --dry-run
wtool provision build/nvim
```

## 项目存根：`install.sh` / `uninstall.sh`

每个项目根目录都有这两个文件，它们是**引擎存根**（内容一样，靠自身文件名判断子命令）：

```sh
#!/bin/sh
# …找到 wtool-bootstrap，然后把活儿交给它
exec "$boot/wtool.sh" "$cmd" "$here" "$@"
```

好处：可以直接 `cd <项目> && ./install.sh`，不用记引擎在哪。
查找顺序：`$WTOOL_BOOTSTRAP` → 向上 4 层找 `bootstrap/` 或 `wtool-bootstrap/` → `~/.wtool/bootstrap`。

**不要手改存根**（它是模板副本）。要改就改 `bootstrap/templates/stub.sh`，
然后用 `wtool scaffold` 重新生成。
