# 07 清单仓待办（你要做的第一件事）

## 先看事实：仓**已经存在**，只是内容不对

我实测过（SSH 可见）：

| 检查 | 结果 |
|---|---|
| `allinkernel/w_manifests` | **存在**，但是**私有**仓（GitHub API 返回 404，SSH 能访问） |
| 它的分支 | `wblog` 和 `wtool`，**两个都指向同一个提交 `036aa0f`** |
| 那个提交的内容 | **还是博客的清单**（build / wblog-ai / template / kernel / rtfsc / std） |
| 你本地 `.repo/manifests/default.xml` | 已经被你改成了 wtool 的清单（2 个项目），但**没有提交** |

也就是说：**仓在，但 wtool 的清单从来没提交上去**。
你现在的 `repo init -b wtool` 拉下来的其实是博客清单，
而本地那份改动一旦被 `repo sync` 覆盖就没了。

---

## 两个选择

### A. 继续用 `w_manifests`，把 wtool 清单提交到 `wtool` 分支

- 好处：不用新建仓
- 坏处：一个仓同时装"博客"和"wtool"两套清单，切分支时容易误 sync
  （现在两个分支内容还一模一样，正是最容易踩坑的状态）

### B. 新建一个只服务 wtool 的清单仓（推荐）

比如 `allinkernel/wtool-manifests`：

- 好处：职责单一，`repo init -u .../wtool-manifests -b main` 不会有歧义
- 代价：多一个仓

## 完整待办清单

### 第 0 步：先把 8 个本地仓推到 GitHub

**当前这 8 个仓只在你本机**，GitHub 上不存在，所以清单写了也拉不到。

```sh
cd ~/self/wtool

# 建议的仓名（与已有的 wtool-astronvim_v5_config 风格一致）
#   bootstrap        -> wtool-bootstrap
#   harness          -> wtool-harness
#   os/ubuntu        -> wtool-os-ubuntu
#   shell/oh-my-zsh  -> wtool-shell-oh-my-zsh
#   shell/zsh        -> wtool-shell-zsh
#   tools/repo       -> wtool-tools-repo
#   terminal/tmux    -> wtool-terminal-tmux
#   terminal/fzf     -> wtool-terminal-fzf

# 逐个推送（git 仓名建好后）：
for spec in "bootstrap:wtool-bootstrap" "harness:wtool-harness" \
            "os/ubuntu:wtool-os-ubuntu" "shell/oh-my-zsh:wtool-shell-oh-my-zsh" \
            "shell/zsh:wtool-shell-zsh" "tools/repo:wtool-tools-repo" \
            "terminal/tmux:wtool-terminal-tmux" "terminal/fzf:wtool-terminal-fzf"; do
    p=${spec%%:*}; r=${spec##*:}
    echo "=== $p -> $r ==="
    git -C "$p" remote remove origin 2>/dev/null
    git -C "$p" remote add origin "ssh://git@github.com/allinkernel/$r.git"
    git -C "$p" push -u origin main
done
```

> 注意：`terminal/fzf` 有 4.4MB 的二进制，推的时候会慢一点，正常。
> `shell/oh-my-zsh` 有 7354 个提交（上游历史），推送也需要点时间。

### 第 1 步：建清单仓 / 提交 wtool 清单

选 A：

```sh
cd ~/self/wtool/.repo/manifests
git add default.xml
git commit -m "wtool 清单：8 个自有项目 + 2 个原有项目"
git push origin HEAD:wtool          # 推到 wtool 分支
```

选 B：

```sh
# 在 GitHub 上新建 allinkernel/wtool-manifests（空的，不要初始化 README）
cd /tmp && rm -rf wtool-manifests && mkdir wtool-manifests && cd wtool-manifests
git init -b main
# 把下面的 default.xml 放进来
git add -A && git commit -m "wtool 项目清单（初版）"
git remote add origin ssh://git@github.com/allinkernel/wtool-manifests.git
git push -u origin main
```

### 第 2 步：新机器上验证

```sh
mkdir -p ~/self/wtool && cd ~/self/wtool
repo init -u ssh://git@github.com/allinkernel/wtool-manifests.git -b main
repo sync -c -j8
```

## 清单文件草稿（可直接用）

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!-- wtool 项目清单 -->
<manifest>
  <remote name="github" fetch="ssh://git@github.com/" />
  <default revision="main" remote="github" sync-j="8" />

  <!-- ===== 引擎：必须最先装 ===== -->
  <project path="bootstrap" name="allinkernel/wtool-bootstrap.git" groups="base">
    <!-- 根目录放一个 install.sh，cd 进来直接跑 -->
    <linkfile src="install.sh" dest="install.sh" />
  </project>

  <!-- ===== 项目记忆与文档 ===== -->
  <project path="harness" name="allinkernel/wtool-harness.git" groups="docs">
    <!-- 让 /README.md 和 /docs 直接可见，任何人 clone 下来就能看 -->
    <linkfile src="doc/README.md" dest="README.md" />
    <linkfile src="doc"          dest="docs" />
  </project>

  <!-- ===== 系统层：换源 + 基础软件包（需要 root）===== -->
  <project path="os/ubuntu" name="allinkernel/wtool-os-ubuntu.git" groups="os" />

  <!-- ===== shell ===== -->
  <project path="shell/oh-my-zsh" name="allinkernel/wtool-shell-oh-my-zsh.git" groups="shell" />
  <project path="shell/zsh"       name="allinkernel/wtool-shell-zsh.git"       groups="shell" />

  <!-- ===== 工具 ===== -->
  <project path="tools/repo" name="allinkernel/wtool-tools-repo.git" groups="tools" />

  <!-- ===== 终端 ===== -->
  <project path="terminal/tmux" name="allinkernel/wtool-terminal-tmux.git" groups="terminal" />
  <project path="terminal/fzf"  name="allinkernel/wtool-terminal-fzf.git"  groups="terminal" />

  <!-- ===== 原有的（已经在 GitHub 上）===== -->
  <project path="editor/vim/astronvim_v5_config"
           name="allinkernel/wtool-astronvim_v5_config.git" groups="editor" />
  <project path="themes/typora/lightmind"
           name="allinkernel/typora-LightMindTheme.git" groups="themes" />
</manifest>
```

### 关于那三条 `linkfile`

它们让 clone 下来的人**第一眼就看到文档**，而且这比手动建软链更规范
（`repo sync` 每次都会保证它们存在）：

| 生成的链接 | 指向 |
|---|---|
| `~/self/wtool/README.md` | `harness/doc/README.md` |
| `~/self/wtool/docs` | `harness/doc` |
| `~/self/wtool/install.sh` | `bootstrap/install.sh` |

> 现在（清单还没配好）我已经**手动**建了这三个软链，功能一样。
> 等你按上面配好清单后，它们会交给 `linkfile` 管理。

### `revision` 的注意点

`<default revision="main"/>` 要求每个仓都有 `main` 分支。
目前 8 个仓**都已经在 `main`**（`master` 已改名），所以不用特殊处理。

如果将来某个仓用了别的分支名，要么改名，要么给那个 `<project>` 单独写
`revision="xxx"`，否则 `repo sync` 会报：

```
fatal: couldn't find remote ref refs/heads/main
```
