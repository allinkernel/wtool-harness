# 02 快速开始

## ⚠️ 先记住顺序（这一步错了会卡住）

```
① 装最小依赖（用系统自带源）→ ② 换镜像源 → ③ 装 wtool 项目
```

原因：`ubuntu:24.04` 这类最小系统里 **`python3` 和 `ca-certificates` 都没有**，
而：

- 引擎依赖 `python3`，没有它什么都干不了
- 先换成 HTTPS 镜像源再装 `ca-certificates`，apt 会因为**无法验证证书**全线失败
- 国内直连 `archive.ubuntu.com` 基本连不上，会一直卡住

而 server/desktop ISO 完整安装的系统里 `python3` 和 `ca-certificates` 是有的，
只缺 `git`。

| 来源 | python3 | git | ca-certificates | apt 源 |
|---|---|---|---|---|
| Ubuntu server/desktop ISO 安装 | ✅ | ❌ 缺 | ✅ | HTTP 官方 |
| Ubuntu **docker 镜像** | ❌ **缺** | ❌ 缺 | ❌ 缺 | HTTP 官方 |

## 场景 A：已经有这套目录（最常见）

```sh
cd ~/self/wtool

# 1) 装引擎自己：建中转链接 + 往 ~/.zshrc / ~/.bashrc 写受管块
./bootstrap/install.sh

# 2) 重开 shell（或 source 一下），让 wtool 命令和变量生效
exec zsh

# 3) 看状态
wtool doctor
wtool list

# 4) 装其余项目
wtool bootstrap --with-system
```

`wtool bootstrap` 会自动扫描工作区里所有 `wtool.xml`，
按 `priority` 从小到大依次执行 `provision`（换源/装包/编译）和 `install`（软链/注入）。

只是想看看它会做什么：

```sh
wtool bootstrap --with-system --dry-run --force
```

> `--force`：仓库有未提交改动时也继续（只是记录的版本号不准）。
> 你自己的仓库平时应该是干净的，只有在改配置还没提交时才需要。

## 场景 B：全新 Ubuntu 24

### 第一步：装最小依赖（唯一一段"裸命令"）

```sh
sudo apt-get update
sudo apt-get install -y --no-install-recommends ca-certificates git python3
```

> 此时用的是系统自带源（HTTP），不需要证书，所以能跑通。
> 这一步**不能省**，也不能和下一步换顺序。

### 第二步：换镜像源

最快的办法是直接交给 wtool（它按发行版自动生成正确的格式）：

```sh
# 前提是已经拿到 wtool 目录（见第三步）；如果还没有，也可以临时手写：
sudo tee /etc/apt/sources.list.d/ubuntu.sources >/dev/null <<'EOF'
Types: deb
URIs: http://mirrors.ustc.edu.cn/ubuntu/
Suites: noble noble-updates noble-backports noble-security
Components: main universe restricted multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg
EOF
sudo apt-get update
```

> 24.04 用的是 **deb822** 格式（`Types:` / `URIs:` / `Suites:` …），
> 不再是 `/etc/apt/sources.list` 里那种 `deb http://...` 一行式。

### 第三步：拿到 wtool 目录

```sh
mkdir -p ~/self/wtool && cd ~/self/wtool
repo init -u <你的清单仓地址> -b main
repo sync -c -j8
```

（清单仓还没配好？见 `07-清单仓待办.md`。）

### 第四步：一键装完

```sh
cd ~/self/wtool
./bootstrap/install.sh
exec zsh
wtool bootstrap --with-system
```

## 场景 C：用 docker 验证（不影响你的机器）

在干净容器里从零跑一遍，容器用完即删，宿主机零改动：

```sh
docker run --rm -it \
  -v ~/self/wtool:/wtool:ro \
  -e GIT_OPTIONAL_LOCKS=0 \
  ubuntu:24.04 \
  bash /wtool/bootstrap/tests/container_test.sh
```

它会：装依赖 → 换源 → 装 6 个项目 → 验证变量/块顺序/软链/shell 函数 →
全部卸载 → 核对 `$HOME` 是否字节级还原。

预期结尾 `PASS: 14  FAIL: 0`。

**网络受限时**加代理（WSL2 要 `--network host` 才能用 `127.0.0.1`）：

```sh
docker run --rm -it --network host \
  -v ~/self/wtool:/wtool:ro \
  -e GIT_OPTIONAL_LOCKS=0 \
  -e http_proxy=http://127.0.0.1:7890 -e https_proxy=http://127.0.0.1:7890 \
  ubuntu:24.04 bash /wtool/bootstrap/tests/container_test.sh
```

## 日常操作

### 装 / 卸一个项目

```sh
cd ~/self/wtool

# 装（在项目目录里，或指定路径）
./terminal/tmux/install.sh
wtool install terminal/tmux

# 看它打算做什么，先不执行
wtool install terminal/tmux --dry-run

# 卸（精确撤销这个项目做过的所有事）
./terminal/tmux/uninstall.sh
wtool uninstall terminal/tmux

# 仓库已经被删了也能卸（按 id）
wtool uninstall --id terminal/tmux
```

### 让改动生效

| 改了什么 | 怎么生效 |
|---|---|
| `env.zsh`（别名、函数、变量） | 重开 shell，或 `source ~/.zshrc` |
| 软链指向的配置文件（如 `tmux.conf`） | 立刻生效（本来就是软链，改仓库文件即改家目录） |
| `wtool.xml`（加了新的 link/env） | 重跑一次 `install.sh` |
| 项目搬家了 | 在新位置重跑 `install.sh`（rc 块不用改） |

### 换源 / 装包（不可逆的那层）

```sh
# 换源（写 /etc/apt/sources.list.d/ubuntu.sources，写前自动备份）
wtool provision os/ubuntu --with-system

# 只看计划
wtool provision os/ubuntu --with-system --dry-run

# 撤销换源（从备份还原）
wtool uninstall os/ubuntu
```

> `--with-system` 是必须的：默认**不动系统**，否则只打印一句"需要 --with-system"就跳过。

### 查看状态

```sh
wtool list       # 当前所有被 wtool 登记的路径 → 属于哪个项目
wtool status     # 检查登记的软链有没有丢
wtool doctor     # 引擎版本、路径、系统信息、已登记条数
wtool env        # 打印可用环境变量（带中文说明），可 eval
```

`wtool env` 的典型用法：

```sh
eval "$(wtool env)"        # 当前 shell 立即生效
wtool env --quiet          # 只要 export 行（可以写进脚本）
wtool env --json           # 给程序解析
```

## 跑测试

```sh
cd ~/self/wtool/bootstrap

./tests/run_all.sh              # pairing 27 条 + provision 24 条
./tests/e2e_repo_sync_test.sh   # 真实 repo init/sync 一遍（本地镜像，不联网）
./tests/container_test.sh       # 容器端到端（需 docker，见场景 C）
```

> `e2e_repo_sync_test.sh` 在 `/tmp` 建工作目录。
> **不要**把它挪到 repo 工作区里面跑，原因见 `06-排错.md` 第一条。
