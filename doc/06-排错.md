# 06 排错

## ⚠️ 第一条：绝不在 repo 工作区内部运行 `repo` 命令

**这条是用两次事故换来的**（详见 `harness/notes/03-hazards.md` G 节）。

> **repo 会从当前目录向上逐级查找 `.repo`**，一旦找到就"复用那个 client"。
> 所以如果你在 `~/self/wtool` 的**任意子目录**里跑 `repo init`，
> 它会直接改写 `~/self/wtool/.repo` —— 也就是你正在用的那个 client。

**症状**：`repo` 命令突然不可用（报 `No module named 'formatter'`），
或者 `.repo/manifests` 变成 "your current branch 'default' does not have any commits yet"。

**规矩**：
- 测试/实验用的工作目录一律用 `mktemp -d`（`/tmp` 下面没有 `.repo` 祖先）
- 跑之前断言：`[ "$(pwd)" = "$EXPECTED" ]`
- 变量用在路径前先检查非空：`[ -n "$d" ] || exit 1`
- `bootstrap/tests/e2e_repo_sync_test.sh` 里已经加了硬性安全闸，照它抄

**万一中招了怎么恢复**：

```sh
# 1) 看 reflog，找到"被改之前"的提交
git -C ~/self/wtool/.repo/repo reflog | head
#    HEAD@{1} = 6d2260b  ← 你 fork 的 wsw 分支 tip
git -C ~/self/wtool/.repo/repo reset --hard 6d2260b

# 2) 还原 manifests 的 remote（原始 URL 保存在 syncstate 里，没丢）
git -C ~/self/wtool/.repo/manifests.git config --get repo.syncstate.remote.origin.url
git -C ~/self/wtool/.repo/manifests.git config remote.origin.url \
    'ssh://git@github.com/allinkernel/w_manifests.git'

# 3) 如果 refs/heads/default 被清掉了（对象还在 packed-refs 里）
git -C ~/self/wtool/.repo/manifests.git update-ref refs/heads/default 036aa0f
git -C ~/self/wtool/.repo/manifests reset -q 036aa0f     # 索引回位，工作区文件不动
```

## 按报错找

### `wtool: error: 缺少依赖: python3 git`

最小系统（docker 镜像、刚装的 server）里没有它们。

```sh
sudo apt-get update && sudo apt-get install -y --no-install-recommends \
    ca-certificates git python3
```

**顺序很重要**：这句话用的是系统自带源（HTTP），不需要证书。
先换成 HTTPS 镜像源再装就会卡在证书验证上。

### `Certificate verification failed: The certificate issuer is unknown`

同上：你在没有 `ca-certificates` 的情况下用了 HTTPS 源。

解决：先用系统自带 HTTP 源装 `ca-certificates`，再换源。
或者干脆把源写成 HTTP（`http://mirrors.ustc.edu.cn/ubuntu/`）——元数据本身有 GPG 签名，安全性不受影响。

### `apt-get update` 卡住不动

国内直连 `archive.ubuntu.com` 基本无响应。换成国内镜像：

```sh
sudo tee /etc/apt/sources.list.d/ubuntu.sources >/dev/null <<'EOF'
Types: deb
URIs: http://mirrors.ustc.edu.cn/ubuntu/
Suites: noble noble-updates noble-backports noble-security
Components: main universe restricted multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg
EOF
sudo apt-get update
```

可选镜像：`mirrors.ustc.edu.cn`、`mirrors.tuna.tsinghua.edu.cn`、`mirrors.aliyun.com`、`mirrors.huaweicloud.com`。

### `git 拒绝使用 ... 的仓库` / `detected dubious ownership`

**容器里以 root 访问宿主目录**时必然出现：文件属主是宿主用户，不是 root。

```sh
git config --global --add safe.directory '*'
```

宿主机上正常使用不会遇到。

### `有未提交的已跟踪改动，请先提交后再 install`

引擎要求仓库干净，这样才能记录"装的是哪个版本"。

```sh
git -C <项目> status          # 看改了什么
git -C <项目> add -A && git -C <项目> commit -m "..."
# 或者临时跳过检查（只是在改配置、还没提交时用）：
wtool install <项目> --force
```

### `dest 已存在且不是软链` / `dest 已是软链且指向别处`

说明 `$HOME` 里已经有个真的文件（或别人的软链）占着这个位置。

```sh
ls -l ~/.tmux.conf            # 看看是什么
wtool install <项目> --force  # 会先备份成 *.wtool-bak.<时间戳> 再接管
```

### `找不到 wtool-bootstrap`

项目存根找不到引擎。三种解法：

```sh
export WTOOL_BOOTSTRAP=/path/to/wtool-bootstrap    # 显式指定
# 或者把 bootstrap 放成项目的兄弟目录 / 上一级
# 或者 git clone <bootstrap 仓> ~/.wtool/bootstrap
```

### `fatal: couldn't find remote ref refs/heads/main`

清单里的 `revision` 和仓库真实分支对不上。

```sh
git -C <项目> rev-parse --abbrev-ref HEAD    # 看真实分支
```

在清单里给那个项目单独写 `revision="master"`，或者把仓库改名：

```sh
git -C <项目> branch -m master main
```

### shell 里没有 `wtool` 命令 / 环境变量是空的

```sh
grep -c '>>> wtool:' ~/.zshrc     # 有块吗
eval "$(wtool env)"               # 手工补一次（不重开 shell）
exec zsh                          # 或者重开 shell
```

如果你 `source ~/.zshrc` 之后还是不行，检查块是不是被删了或者项目路径挂了：

```sh
ls -l ~/.wtool/links/             # 中转链接还在吗
wtool status                      # 哪些登记的软链丢了
```

### `[oh-my-zsh] Insecure completion-dependent directories detected`

oh-my-zsh 自带的安全检查：`$ZSH/custom` 的属主不是当前用户，或 group/other 有写权限。

- **容器里以 root 访问宿主目录**：必然出现，正常现象
- **自己机器上**：`compaudit | xargs chmod g-w,o-w`

不要为了消掉它去设 `ZSH_DISABLE_COMPFIX=true` —— 那会把一个真实的安全提醒永久静音。

### ansible 的 task 卡住不动，只有 `TASK [安装基础软件包] ***`

三种可能，按概率排：

1. **它在静默下载**（最常见）。`ansible.builtin.package` 一个 task 装几十个包，
   **跑完才输出**，中间几分钟完全没有反馈。clang+llvm+emacs 那一串 1GB+。
   另开终端看：
   ```sh
   docker exec -it <容器> bash -c 'ps aux|grep -E "apt|dpkg"|head; du -sh /var/cache/apt/archives'
   ```
   缓存在涨 → 只是慢，等着；不耐烦就 `Ctrl+C` 改用轻量模式（见下）。

2. **debconf 交互提示把它挂死了**（无人值守环境没人回答）。
   已在 playbook 里加了 `environment: DEBIAN_FRONTEND=noninteractive`，
   引擎执行任务时也会注入这个变量。

3. **网络到不了镜像源**。apt 会一直重试，看起来也像"卡住"。

**轻量模式**（只装让 shell 能跑起来的东西，几十秒）：

```sh
docker run --rm -it -v ~/self/wtool:/wtool:ro \
  -e WTOOL_ARGS=--install-only \
  ubuntu:24.04 bash /wtool/bootstrap/scripts/container-shell.sh
```

**重型工具链是可选的了**：clang / llvm / gcc / gdb / emacs + 多架构开发库
（1GB+）现在由 `env:WTOOL_HEAVY` 控制，默认**不装**。要装：

```sh
docker run --rm -it -v ~/self/wtool:/wtool:ro -e WTOOL_HEAVY=1 \
  ubuntu:24.04 bash /wtool/bootstrap/scripts/container-shell.sh
```

### 非交互 bash 里 fzf/别名不生效

Ubuntu 默认 `~/.bashrc` 开头有"非交互就直接 return"的守卫：

```sh
case $- in *i*) ;; *) return;; esac
```

所以 `bash -c '...'` 根本执行不到追加在末尾的 wtool 块。这是 Linux 的标准行为，
**交互式终端里是正常的**。要在脚本里用，得显式 source：

```sh
bash -c '. ~/.wtool/links/terminal/fzf/env.bash; command -v fzf'
```

### 卸载后 `$HOME` 里多了东西

先确认是不是 wtool 造成的：

```sh
wtool list                                  # wtool 登记的路径
find ~ -maxdepth 1 -newermt '-1 hour'       # 最近一小时内新建的
```

有几类**不是** wtool 建的，属正常：

| 东西 | 谁建的 |
|---|---|
| `~/.zcompdump*` | zsh 自己的补全缓存 |
| `~/.cache/oh-my-zsh/*`（含 `~/.cache` 本身） | source oh-my-zsh 时它自己建的 |

### 在容器里跑测试，`apt` 报证书错 / 卡住

见 `02-快速开始.md` 场景 C，那里给了带代理的完整命令
（WSL2 下要加 `--network host`，否则容器里的 `127.0.0.1` 不是宿主）。

## 调试技巧

```sh
# 任何破坏性操作先干跑
wtool install <项目> --dry-run
wtool provision <项目> --with-system --dry-run

# 单独校验一个项目（不做事）
wtool validate <项目>

# 看状态目录里到底记了什么
cat ~/.local/state/wtool/registry.tsv
cat ~/.local/state/wtool/<项目id>/journal.tsv
cat ~/.local/state/wtool/<项目id>/meta.tsv

# 引擎语法自检（改过引擎之后）
cd ~/self/wtool/bootstrap
sh -n wtool.sh && sh -n lib/wtool_fs.sh && python3 -m py_compile lib/wtool_plan.py

# 全量测试
./tests/run_all.sh
```
